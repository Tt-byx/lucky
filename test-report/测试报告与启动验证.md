## 三、发现的问题、根因与处理

### ✅ P1-1　扫码登录 / WebSocket 在线数接口被错误要求鉴权（已修复并回归）

- **现象**：`POST /api/scan/login` 无 token 调用返回 `HTTP 403`；`GET /api/ws/online` 同样 403。而扫码令牌是 UUID、不是 JWT，带上也会被 JWT 过滤器拒绝 → **移动端主流程完全不可用**。
- **根因**：`SecurityConfig` 白名单仅放行了 `activity/current`、`activity/history`、`participant/**`、`danmaku/send`、`screen/config`、`screen/danmaku-settings`、`/ws/**`、swagger、actuator、`auth/login`，**缺少 `/api/scan/**` 与 `/api/ws/**`**，落入 `anyRequest().authenticated()`。
- **修复**：`SecurityConfig.java` 增加两条 `permitAll()`。
- **回归**：扫码登录/校验/登出 8 个用例全部通过；`/api/ws/online` 免鉴权返回 `count`。

### ✅ P1-2　初始化敏感词乱码，导致敏感词过滤整体失效（已修复并回归）

- **现象**：`GET /api/sensitive-word/list` 返回 `å‚»é€¼` 之类乱码；发送“傻逼测试”**未被拦截**（`code=200`），违规弹幕被异步入库。
- **根因**：`Dockerfile.mysql` 构建的 MySQL 容器在初始化时执行 `schema.sql`，容器 locale 为 POSIX，**`mysql` CLI 客户端默认字符集回退到 latin1**，`INSERT` 的中文字面量被二次编码后存入 `utf8mb4` 列。
  证据：`SELECT HEX(word)` 得到 `C3A5E2809A...`（UTF-8 二次编码），而经 JDBC 写入的词为正确的 `E689B9...`。
- **修复**：`schema.sql` 首行加 `SET NAMES utf8mb4;`；`Dockerfile.mysql` 加 `ENV LANG=C.UTF-8` 兜底。
- **回归**：`HEX(word)` 为 `E582BBE980BC`（“傻逼”正确编码）；中文校验用例通过；内置词与新增词均能被 `403` 拦截。

### ✅ P1-3　同一抽奖轮次可被重复抽取，造成奖品超发（已修复并回归）

- **现象**：轮次 `winner_count=2`，连续两次调用 `POST /api/lottery/draw/{roundId}` 均返回成功；DB 中同一轮次出现 **3 条** `winner` 记录。第二次调用的报错与首次相同，说明轮次“已完成”状态对第二个请求不可见。
- **根因**：`LotteryDrawService` 中「校验轮次状态」读 DB，而「把轮次置为已完成」放在 `CompletableFuture.runAsync` 异步块里。第一个请求返回时异步任务往往尚未写库，第二个请求读到 `status=0` 便再次抽奖。分布式锁只能串行化并发，无法阻止这种**串行重放**。
- **修复**：把轮次状态更新移到 `doDraw()` 主流程中同步落库（返回前生效），并从异步块中移除该更新。
- **回归**：首次抽奖返回 2 人且 `winner` 表 2 行；紧接的第二次抽奖返回 `code=500 该轮次已完成抽奖`。

### ✅ P2-4　删除/更新活动后「当前活动」缓存不失效，返回已删除活动（已修复并回归）

- **现象**：`GET /api/activity/current` 命中缓存后，即使活动已被删除，最长 5 分钟内仍返回该活动。
- **根因**：`ActivityServiceImpl` 只在 `createActivity` 中清理 `lucky:activity:current`，而 `updateById` / `removeById` 未清理。
- **修复**：重写 `updateById`、`removeById`，操作后清理该缓存。
- **回归**：专项用例「创建 B → current 命中 B → 删除 B → current 回退到 A」通过（`current.id=3`，修复前会返回已删除的 `4`）。

### ✅ P2-5　MySQL 服务未挂数据卷，容器重建即丢库（已修复）

- **现象**：`docker-compose.yml` 中 `redis` 有 `redis-data` 卷、`rabbitmq` 有 `rabbitmq-data` 卷，**`mysql` 没有任何卷**，数据写在容器可写层，`docker compose down`/重建容器后数据全丢。
- **修复**：新增 `mysql-data:/var/lib/mysql` 卷。
- **注意**：如需重置数据库，执行 `docker compose down -v` 后再 `up`（否则 `docker-entrypoint-initdb.d/init.sql` 不会重新执行）。

### ⚠️ P2-6　背景图上传不可用：OSS Bucket 不存在（**未改动代码，需你决策**）

- **现象**：`POST /api/screen/background` 上传 1×1 PNG，返回 `code=500 文件上传失败: The specified bucket does not exist. [ErrorCode]: NoSuchBucket`。
- **根因**：`application-prod.yml` 中 `alibaba.oss.bucket-name: ttbyx`、`endpoint: oss-cn-beijing.aliyuncs.com`。凭据有效（已成功鉴权并发出请求），但**该 Bucket 不存在或不在该 Region**。
- **影响**：活动背景图/视频、手机端背景上传功能不可用；其余接口不受影响。
- **建议**：改 `.env`/配置里的 `bucket-name` 与 `endpoint` 为你在 OSS 控制台的真实值；或去掉 OSS 配置改用本地存储（`FileUploadUtil` 已有本地 `uploads/` 实现，但目前未被 `ScreenConfigServiceImpl` 使用）。

### ⚠️ P2-7　`.env` 中明文存放真实阿里云 AK/SK（**建议处理**）

- `.env` 内 `OSS_ACCESS_KEY_ID` / `OSS_ACCESS_KEY_SECRET` 为明文真实凭据，且 `docker-compose.yml` 会读取并注入容器环境变量。
- 好消息：`.gitignore` 已包含 `.env`，不会误提交仓库。
- **建议**：该 AccessKey 已在本机明文存留且被用于真实 OSS 调用，建议在阿里云控制台**轮换**一次，并通过系统环境变量或密钥管理注入。

### ⚠️ P3-8　业务错误统一返回 HTTP 200（REST 语义不规范，未改动）

- 所有业务失败（含 401/403/429/500）HTTP 状态码都是 `200`，错误码放在 `Result.code`。前端需自行判断 `code`；对第三方/网关监控不友好。
- **建议**：如需规范，可在 `GlobalExceptionHandler` 中按 `BusinessException.getCode()` 映射 HTTP 状态码。

### ⚠️ P3-9　删除活动不清理派生 Redis 键（低风险，未改动）

- `lucky:activity:current` 已修复；但 `lucky:lottery:win:count:<activityId>:<participantId>`（24h）、`lucky:prize:*`、`lucky:participant:count:*`、`lucky:screen:config` 不随活动删除清理。
- **影响**：仅当 `activityId` 被复用时才会脏读（本次测试第一轮就复现过：旧中奖计数把候选参与者全部过滤，抽奖报“所有参与者均已达到最大中奖次数”）。现在 MySQL 已持久化，`activityId` 不再复用，实际风险低。
- **建议**：活动删除流程中显式清理上述键（需给 `RedisUtil` 加 `deleteByPattern`）。

## 四、docker compose 启动验证

### 4.1 编排调整（因本机端口占用）

本机 `3306` 被 Windows 服务 `MySQL96`、`5672/15672` 被 `RabbitMQ` 服务占用，且当前账号非管理员无法停止服务，故采用**宿主机端口重映射**（容器内端口不变，服务间通过 compose 网络名互访，后端配置无需改动）：

| 服务 | 镜像 | 容器名 | 宿主机端口 → 容器端口 |
|---|---|---|---|
| MySQL | `lucky-mysql`（构建，基于 `mysql:8.0` + `schema.sql` 初始化） | `lucky-mysql` | **3307 → 3306** |
| Redis | `redis:7-alpine` | `lucky-redis` | 6379 → 6379 |
| RabbitMQ | `rabbitmq:3-management-alpine` | `lucky-rabbitmq` | **5773 → 5672**、**15673 → 15672** |
| 后端 | `lucky-backend`（构建，Maven 打包 + JRE17，`profile=prod`） | `lucky-backend` | 8080 → 8080 |
| 前端 | `lucky-frontend`（构建，3× Vue 打包 + nginx） | `lucky-frontend` | 5173/5174/5175 |

> 说明：`5673` 落在 Windows 保留端口区间 `5673-5772`（`netsh int ipv4 show excludedportrange protocol=tcp`），故 AMQP 改用 `5773`。
