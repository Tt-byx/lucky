# 2026-10-09 工作日志

## lucky 抽奖系统：全接口测试 + docker compose 全量启动

### 环境处置（重要）
- 本机 `3306` 被 Windows 服务 `MySQL96` 占用、`5672/15672` 被服务 `RabbitMQ` 占用；当前账号非管理员，**无法停止这两个服务**。
- 结论：采用**宿主机端口重映射**方案（容器内端口不变，服务间走 compose 网络名，后端配置无需改）：
  - mysql `3307:3306`、rabbitmq `5773:5672` + `15673:15672`
  - 注意：`5673-5772` 属于 Windows 保留端口区间（`netsh int ipv4 show excludedportrange protocol=tcp`），不可用。
- `docker-compose.prod.yml` 同步做了相同端口调整。

### 修复的缺陷（均已回归验证）
1. **`SecurityConfig`** 白名单缺 `/api/scan/**` 与 `/api/ws/**` → 扫码登录（移动端主流程）与在线人数接口被误要求 JWT。已加 `permitAll()`。
2. **敏感词乱码**：MySQL 容器初始化时 `mysql` CLI 客户端字符集为 latin1，`schema.sql` 中文被二次编码 → 敏感词过滤完全失效。修法：`schema.sql` 首行加 `SET NAMES utf8mb4;` + `Dockerfile.mysql` 加 `ENV LANG=C.UTF-8`。
3. **抽奖重复抽取**：`LotteryDrawService` 把「轮次置为已完成」放在 `CompletableFuture` 异步块中，串行重放能再抽一次（实测轮次配 2 人却落库 3 条 winner）。修法：轮次状态改为 `doDraw()` 同步落库，异步块只保留 winner/participant 写入。
4. **活动缓存不失效**：`ActivityServiceImpl` 只在 create 时清理 `lucky:activity:current`，删除/更新后 `/api/activity/current` 最长 5 分钟返回已删除活动。修法：重写 `updateById` / `removeById` 清理缓存。
5. **MySQL 缺数据卷**：compose 里 mysql 无 volume，容器重建即丢库。已加 `mysql-data:/var/lib/mysql`（重置需 `docker compose down -v`）。

### 测试过程中的坑（避免重踩）
- `@RateLimit`（弹幕 1 条/秒/participantId）会让「连续测同一参与者」的用例串扰，报 429 而非预期错误码 → 每条断言要用**独立参与者**。
- 敏感词/活动等 Redis 缓存跨容器复用（redis 有持久卷）→ 跨轮次测试会出现脏读，需 `redis-cli FLUSHALL` 或换新 activityId。
- 弹幕/中奖记录是**异步入库**，断言前需 `sleep` 等待。
