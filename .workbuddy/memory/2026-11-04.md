# 2026-11-04

## 抽奖项目业务重构：管理员随机抽人 → 用户限时抢奖（秒杀）

### 背景
用户决定把项目从「管理员一键随机抽人」改成「用户点抢奖」，走秒杀模型，
目的是在简历上讲清「库存预扣 / 防超卖 / MQ 异步落库」这条链路。

### 数据模型变更
- `lottery_round` 新增 `prize_id`（轮次必须绑定奖品）、`start_time`、`end_time`；
  status 语义改为 0待开始 / 1抢奖中 / 2已结束 / 3已取消。
- `winner` 升级为「抢奖订单」：新增 `activity_id`、`prize_id`、`status`、`claim_code`，
  加两个唯一索引 `uk_round_participant`、`uk_activity_participant`（一人一活动只能中一次）。
- `participant.status` 拆为 `lottery_status`（只管抽奖资格 1/3），中奖事实由 winner 表表达。
- `prize` 拆出 `total_stock`（配置值）与 `stock`（剩余）。

### 秒杀链路
- 新增 `SeckillService` / `SeckillServiceImpl`：preheat（开轮预热）、join（抢奖）、rollback（补偿）。
- 新增 `lua/seckill.lua`：库存判断 + 本轮去重 + 跨轮次去重 + DECR + SADD 一次原子完成。
- 新增 `lua/seckill_rollback.lua`：MQ 失败时回滚预扣。
- 新增 MQ 队列 `lucky.lottery.join.queue`，消费者做幂等 + DB 条件扣库存 + 唯一索引兜底 + 广播。
- 接口：`POST /api/lottery/round/{id}/start|end`、`POST /api/lottery/join/{roundId}`（需扫码令牌）、
  `GET /api/lottery/result`、`GET /api/lottery/remaining`。
- 删除 `LotteryDrawService`（随机抽人逻辑）与 `/api/lottery/draw/{roundId}`。

### 顺手修掉的 bug
- 禁言/移出后不清 Redis 状态缓存，导致禁言最长 1 小时不生效。
- MQ 队列级 `x-message-ttl=30s` 会把积压中的正常消息误投死信，已移除。
- MQ 重试计数用 `deliveryTag` 会复用/归零，改用业务 `messageId`，并加消费幂等。
- Sentinel 限流资源名还指向已删除的 `draw` 接口，改为 join 接口（QPS 800，快速失败）。
- 创建奖品时 totalStock 为空会让库存回补条件永远不成立，PrizeServiceImpl.save 里兜底。
- 扫码登录的 name 从 `@NotBlank` 改为 Service 层判断（老用户快速进入不传姓名）。

### 环境问题
- Maven 3.9 报「present, but unavailable」：本地仓库缓存标记是 `central`，但 settings.xml 的
  mirror id 是 `aliyunmaven`，Maven 认为来源不可信要重新下载，而 TLS 握手失败。
  修复：把 mirror id 改成 `central`（已备份 `~/.m2/settings.xml.bak`）。
- 容器内 Maven 直连中央仓库太慢，新增 `docker/maven-settings.xml` 走阿里云，Dockerfile.backend 引用。
